# 诊断任务

只诊断开头约 60 秒,分两段检查。

## 第一段:前 30 秒(0:00–0:30)

检查有没有告诉观众这三件事:

1. 现象 — 观众能看到一个具体、可感知的现象、场景或事实,而不是抽象概念
2. 冲突 — 现象中存在反差、矛盾或悬念(认知冲突或核心矛盾),让人想问"为什么"
3. 本质 — 是否点明(或强烈暗示)现象背后的本质、核心问题

## 第二段:30–60 秒(0:30–1:00)

检查有没有讲清"这条视频到底会给观众什么"(价值承诺):

- 是知识拆解?是方法?是认知纠偏?是具体步骤?
- 承诺可以明示也可以是强有力的暗示,但观众必须能预期"看完这条视频我会得到什么"
- 只继续扩大冲突、却不给任何内容预期,属于承诺缺失

## 承诺与内容一致性(唯一使用全文的判断)

结合全文结构判断开头的价值承诺与后文实际交付是否匹配:

- 开头做出的承诺,后文没有对应交付 → promise_mismatch
- 开头没有任何承诺,但后文其实有明确的内容类型 → value_promise_missing,建议按后文实际内容补写承诺句
- 开头的承诺与后文交付一致 → 不产生此类命中

全文仅用于这一判断与内容类型定位,不要对开头以外的内容产生命中。

---

# 命中分类(type)

1. phenomenon_missing — 现象缺失/不清:开头没有具体现象,或现象太抽象、观众无法代入
2. conflict_weak — 冲突不足:现象平淡,没有反差、矛盾或悬念,观众没有理由继续看
3. essence_missing — 本质未点明:只描述了表面,没有点出或暗示背后的核心问题/本质
4. value_promise_missing — 价值承诺缺失:30–60 秒没有让观众预期会得到什么
5. hook_weak — 钩子/节奏弱:开场句不抓人、铺垫拖沓、信息密度低、迟迟不进正题
6. promise_mismatch — 承诺与内容不符:开头承诺的内容类型与后文实际交付不一致

---

# 修改模式(mode)

- replace — 改写既有句子:suggestion 为可直接替换 original 的完整新文本
- insert_after — 需要插入新内容:original 为"应插入位置"的锚点句,suggestion 必须 = 锚点原句全文 + 紧随其后的新句子(替换后锚点句保持原样,新句紧跟其后)

缺失类问题(value_promise_missing、phenomenon_missing 等)通常用 insert_after;不足类问题(conflict_weak、hook_weak、essence_missing、promise_mismatch)通常用 replace。

---

# 硬约束

- original 必须是脚本正文的逐字连续片段(含标点),禁止改写、拼接、翻译或大小写调整
- original 必须位于上方"开头范围"声明的章节内;禁止引用章节标签行([CHxx | ... | ...])
- suggestion 使用脚本的原文语言,必须是可直接落地的完整文本;reason、original_zh、suggestion_zh 使用中文
- 每条命中给出 segment:s0_30(前 30 秒)或 s30_60(30–60 秒),按 original 的实际时间位置判定(依据章节时间标签,章内按比例推算)
- 宁缺毋滥:只报告真正影响开头留存的问题,每条都必须附可执行的修改建议;没有问题就返回空 hits

# 评分参考

- 前 30 秒:现象/冲突/本质三项都有且强 = 9–10;都有但偏弱 = 6–8;缺一项 = 4–6;缺两项以上 = 0–3
- 30–60 秒:承诺明确且与后文匹配 = 9–10;承诺模糊或类型不清 = 5–7;完全无承诺 = 0–4
