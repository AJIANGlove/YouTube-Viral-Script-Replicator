怎么修:
1. 每一行分两种:
   - 原始数:从事实表来的数(写 fact_ids),或者明确的假设(item 里写「假设」两个字,例如「하루 판매량(假设)」)。不写 formula。
   - 算出来的数:合计、利润、保本点、换算,一律写 formula(只用行编号、数字和 + - * / ( ),例如 "L4-L5-L6"、"L3*L2*L1"、"L12/(1-L9)")。amount 写你算的数就行,程序会按公式重算并以程序的为准。
2. 引用的行必须排在前面(公式里不能引用后面的行)。
3. 单位统一:钱一律用「원」,不要用「万韩元」「만원」(3,000만 원 写 amount 30000000、unit "원/월");周期写在单位斜杠后面:원/월、원/일、원/년、원/개、개/일。加减只能在同单位、同周期之间;月和天之间换算要写成乘除(例如 "L10/L3",L3 是每月营业天数)。比例单独一行,unit 写 "%",amount 写 40.7 这种,用到时写 "L7*L9/100"。
4. 程序已经把算错的行改成按公式算的数了。如果问题里说「差得多」,先判断是公式引用错了行,还是原来的数本来就不对:公式错了就改公式;原来的数不对就保留公式。
   问题里说「多半是漏了或低估了成本」的行(你写的总数比各项加起来大很多):这是漏了成本,不是总数写错。把漏掉的成本一项一项补成新行(房租要和店面面积对得上,人手要够接待每天的客流,还有税、保险、折旧、设备维护、损耗……),加进这一行的公式,补到按公式算出来和原来写的数差不多;不要把总数改小去迁就公式。
   问题里说「利润率」「回本」不合理的:按上面同样的办法重查成本和开店投资;查完还是这么高、这么快,在 notes 里写清依据。
5. 没出处的原始数:事实表里有对应的就补 fact_ids;没有就在 item 里标「假设」,并保持一个合理、好念的数。不要编新事实。
6. 不要为了让结果好看改原始数。除了上面「漏了成本」「利润率/回本不合理」要补的成本行,不要加事实表里没有的成本项目。
7. 行编号尽量沿用原来的;删掉没用的行可以,新增的行编号接在后面。

经济拆账账本的样子(经济拆账题才用;一家店,按观众听的顺序排):
- 原始数:객단가/한 개 가격、하루 판매량、한 달 영업일수、각 비용(재료비율 %、월세、인건비、공과금、카드·배달 수수료율 % …)、사장 본인 노동시간·시급(사장이 직접 일하면)
- 算出来:월 매출 = 객단가 × 하루 판매량 × 영업일수
- 算出来:각 변동비 = 월 매출 × 비율 / 100
- 算出来:월 영업이익 = 월 매출 - 비용1 - 비용2 - …(一项一项减,程序会按这个顺序排念账表)
- 算出来:사장 인건비 = 시간 × 시급;사장 실질 이익 = 영업이익 - 사장 인건비;가족 실제 수령 = 영업이익
- 算出来:손익분기 월 매출 = 고정비 합계 / (1 - 변동비율 합계/100);하루 손익분기 판매량 = 손익분기 월 매출 / 객단가 / 영업일수
- 有好月、坏月对比时:只换「하루 판매량」这一类原始数,另起一组行,公式照抄

只输出一个 JSON,不要代码围栏和解释:
{"ledger": [{"id": "L1", "item": "", "value": "", "amount": 0, "unit": "", "formula": "", "fact_ids": []}], "notes": "一句话说改了什么"}
ledger 要输出**完整的新账本**(所有行,不是只给改的行)。
