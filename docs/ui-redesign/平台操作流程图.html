爆款文案生成平台 · 现状操作流程总览

供 UI/UX 改版讨论使用 · 与代码版本 v1.2 对应（app/README.md 为准） · 生成日期 2026-10-23

0这是个什么产品

局域网内部工具（无登录、多人共用）：把"已验证的爆款视频框架"（资产库里的拆解 JSON）套到新选题上，由 LLM 管线自动产出多语言口播文案，再做人工微调，最后一键推送到视频生成网站出片。

用户操作 系统自动 / LLM 质量闸门（程序校验） 需人工确认 / 决策点 完成 / 产物 失败 / 中断

1信息架构（现状）

顶部 4 个平级导航 + 2 个不在导航里的页面。单文件 SPA（app/public/index.html，约 4500 行，HTML/CSS/JS 全部内联，无框架无构建）。

① 文案创作 默认页

  • 第 1 步：选框架资产 （卡片网格 + 搜索/排序/频道筛选）
  • 第 2 步：主题与受众 （赛道+推荐选题、新主题、频道、目标语言×12、国家×13、受众、时长、写前分析勾选、参考资料、频道声音）
  • 「开始生成」→ 创建任务

② 任务 列表

  • 10 列表格：主题/框架/目标/频道/状态/视频/步骤/创建/结束/操作
  • 筛选：关键词、时间、状态 chip×7、语言 chip、视频状态 chip、只看爆款
  • 3 秒轮询；分页 50/页；爆款 ☆ 标记；取消 / 失败重试
  • 「刷新视频状态」按钮

③ 资产库

  • 框架资产卡片网格 （样本数/语速/章数等）
  • 搜索 / 排序 / 频道 chip
  • 点卡片 → 独立页「原文对照」（/source.html?id=…，双语 SRT 对照）
  • 界面上没有上传入口（资产靠预置或调 API）

④ 设置 5 张卡平铺

  • 频道声音设定 （AI 起草 + JSON 编辑）
  • 联网搜索 （渠道/开关/Key）
  • 视频网站绑定 （全局单账号）
  • 主流程 API 配置 （渠道/模型/参数）
  • 微调按钮 API 配置 （独立第二套）
导航外页面：任务详情页（从任务列表点进，见第 4、5 节）· 原文对照页（资产库点入）。

3任务状态机（任务列表的"状态"列）

排队中 queued→ 写前分析中 analyzing→ 待确认分析 awaiting_review→ 生成中 running（step1-4）→ 完成 done （不勾选写前分析时：排队中 → 生成中 → 完成；任何时刻可取消 → 已取消 cancelled；闸门/出错 → 失败 failed，可重试）
⚠ awaiting_review 是"停摆等人工"状态：不点确认任务永远不往下走；目前只有列表徽章和详情页能看到它，没有全局提醒。另有一套并行的视频状态：未推送 / 草稿 / 生产中 / 已暂停 / 已完成 / 失败。

6两条典型用户旅程

A. 首次使用（配置期，只此一次）

  1. 开「设置」→ 配主流程 API（渠道/模型/Key）← 不配则全部功能不可用
  2. 配微调按钮 API （可同一渠道）
  3. （可选）开联网搜索、绑定视频网站、建频道声音
  4. 去「资产库」确认有可用框架 （资产靠预置，界面无上传入口）
  5. 进入日常旅程 B

B. 日常创作（每条文案）

  1. 「文案创作」选框架 → 填主题/语言/受众 → 开始生成
  2. （默认）等写前分析 → 去详情页核对并确认 ← 容易卡住的点
  3. 等 3-8 分钟 → done → 详情页看 V1/V2
  4. 按需：生成简介 / 指纹检测 / 商业化检查 / 留存检查 / 强化开头
  5. 核对 fact_check_list 里的待核实事实
  6. 选版本推送视频网站 → 出片发布
  7. 发布后回任务列表标 ☆ 爆款 （沉淀哪些选题真爆了）

7已观察到的可用性痛点（改版重点候选）

  • 前端是 4500+ 行单文件（HTML/CSS/JS 全内联，约 256KB），无组件、无设计系统，各面板样式各自手写。改样式风险高、新功能越堆越乱——改版需顺带考虑代码组织。
  • 任务详情页信息垂直无限堆叠：进度、写前分析、留存检查、4 张版本卡、3-4 个检测面板、事实清单全部塞在一页，动辄滚十几屏。找不到入口、版本对比困难。
  • 每张版本卡标题栏 6-7 个按钮（4 张卡共约 26 个按钮），视觉噪音大，主次不分。高频操作（复制/看文案）与低频操作（各类检测）没有分层。
  • V1 / V1.5 / V2 / V2.5 版本命名不直观，演化规则只在 README 里有。新人不知道哪个是"最新可用稿"、该推哪个版本出片。
  • awaiting_review 停摆状态无全局提醒，入口只有列表小徽章。任务卡住用户却不知道，白等。
  • 设置页 5 张配置卡平铺、无顺序引导，首次使用不知道"必须先配主流程 API"，也没有任何 onboarding / 空状态指引。新用户第一步就迷路。
  • 创作页第 2 步 10+ 字段平铺，必填/选填不分组，高级选项（声音、参考资料）与基础项混排。表单压迫感强。
  • 任务列表 10 列 + 多排筛选 chip，状态徽章两套色系（任务 7 态 + 视频 6 态）叠在一行。信息密度高，扫读困难。
  • 资产库没有上传入口（只能预置或调 API），也没有空状态引导。想加新框架得找会调 API 的人。
  • 检测类面板（指纹/商业化/留存/稿件检查/写前分析）交互范式相似但各画各的：都是"列表问题→逐条采纳/忽略→写回版本"。本可以统一成一套"审阅工作台"组件。
