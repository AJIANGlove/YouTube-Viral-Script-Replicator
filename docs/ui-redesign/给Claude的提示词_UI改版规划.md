# 给 Claude 的 UI/UX 改版规划提示词

## 使用说明（先读这段）

1. **推荐对话方式**：在 claude.ai 开一个新对话（或用 Claude Code 打开本仓库），按下面"附件清单"上传材料，然后把"提示词正文"整段发出去。
2. **附件清单**（按优先级）：
   - 必给：`docs/ui-redesign/平台操作流程图.html`（现状流程总览，本目录已生成）
   - 必给：`app/README.md`（功能与规则的权威说明）
   - 强烈建议：平台 5 个页面的**截图**（文案创作两步、任务列表、任务详情页、设置页、资产库），截图比文字更能让 Claude 看懂现状
   - 可选：`app/public/index.html` 源码（256KB，网页版 Claude 放不下就别给，Claude Code 里直接让它读文件即可）
3. **分两轮聊效果更好**：第一轮只发提示词正文（让 Claude 先诊断、提问、给方向）；第二轮再发"追加追问"里你关心的条目。
4. 提示词里【】包住的地方是需要你按实际情况填的。

## 提示词正文（整段复制发给 Claude）

````text
你是一位资深的产品设计师（UX/UI）兼前端架构师。我有一个自用的内部工具，功能已经完整、逻辑稳定，但界面样式和操作流程很难用。请你帮我系统性地重新规划它的界面与交互。

# 一、产品背景

- 产品名：爆款文案生成平台。局域网内部工具（http://局域网IP:8080），无登录、3-5 人小团队共用。
- 干什么的：把"已验证的爆款 YouTube 视频框架"（资产库里预置的拆解数据）套用到新选题上，由 LLM 管线自动生成多语言口播文案（蓝图→写稿→审核→终稿 四步，带质量闸门和可选的"写前分析"人工确认环节），然后人工做检查微调（指纹检测/商业化检查/开头留存检查/强化开头/生成视频简介），最后一键推送到视频生成网站自动出片。
- 用户：我自己和团队成员，内容创作者，不是技术人员；每天都在用，桌面浏览器为主。
- 界面语言：中文。

# 二、技术现状与约束

- 前端：单个文件 app/public/index.html（约 4500 行 / 256KB），HTML+CSS+原生 JS 全部内联，无框架、无构建工具、无组件化。另有一个独立小页 source.html（原文对照）。
- 后端：Node.js 原生 http 模块（无 Express），只提供 JSON API + 静态文件服务。数据存在文件系统 JSON。
- 约束（请严格遵守）：
  1. 后端 API 尽量不改；改版以前端重组为主。
  2. 不引入重型前端框架和构建链（React/Vue/Webpack 都不要）；最多允许把单文件拆成几个静态文件 + 轻量模块化（原生 ES Modules）。保持"node server.js 启动即可用"。
  3. 桌面优先，不需要移动端适配。
  4. 局域网内部工具，不需要登录/权限设计。

# 三、现状材料

我上传了：
1. 《平台操作流程图.html》——现状的信息架构、端到端主流程、任务状态机、详情页操作矩阵、出片链路、用户旅程、以及我自己总结的 10 条可用性痛点。请先完整阅读它。
2. 《README.md》——每个功能的详细规则（版本演化 V1/V1.5/V2/V2.5、写前分析、质量闸门、各类检查的写回规则等）。
3. 各页面截图。（如有）

# 四、我认为的痛点（供你参考，你可以补充和挑战）

1. 详情页信息无限垂直堆叠：进度、写前分析、留存检查、4 张版本文案卡、3-4 个检测面板、事实清单全在一页，动辄十几屏。
2. 每张版本卡标题栏塞 6-7 个按钮（4 张卡约 26 个），高频（复制）和低频（各类检测）操作没有分层。
3. V1/V1.5/V2/V2.5 版本命名和演化规则不直观，新人不知道"哪个是最新稿、该推哪个出片"。
4. "待确认分析"（awaiting_review）是停摆等人的状态，但无全局提醒，任务卡住了用户不知道。
5. 设置页 5 张配置卡平铺无引导，首次使用不知道必须先配 API；全站无 onboarding / 空状态。
6. 创作页表单 10+ 字段平铺，必填/选填不分组。
7. 任务列表 10 列 + 两套状态徽章体系（任务 7 态 + 视频 6 态），密度高。
8. 资产库无上传入口、无空状态。
9. 各"检测审阅"面板（指纹/商业化/留存/稿件检查/写前分析）交互范式相同（列问题→逐条采纳→写回版本）但样式各自为政。
10. 单文件 4500 行无组件化，改样式风险高。

# 五、请你交付的内容（按顺序）

## 第 1 步：现状诊断
- 基于材料指出我理解之外的 UX 问题；把问题按"信息架构 / 流程 / 交互 / 视觉"四类分组，标严重程度。
- 在开始设计前，先向我提问澄清（比如：哪些操作最高频、谁最常用、最痛的场景），最多 10 个问题，等我回答后再继续。

## 第 2 步：目标信息架构方案
- 给 2-3 个导航与页面重组方向（例如：按"任务为中心"重组 vs 按"工作流阶段"重组 vs 保持四导航但重做详情页），每个方向给：结构图、优缺点、实施成本（哪些 API/页面要动），并给出你的推荐和理由。

## 第 3 步：关键页面设计（对推荐方向）
- 任务详情页（重点中的重点：4 版本 × 6+ 操作的组织方式，检测审阅的统一范式，版本演化如何可视化）
- 任务列表页（状态可视化、awaiting_review 如何不被忽视、爆款标记）
- 文案创作页（表单分组、步骤感）
- 首页/仪表盘（如果需要的话）+ 首次使用引导
- 每个页面给：布局结构说明 + ASCII 线框图 + 关键交互说明（点哪里发生什么、什么状态显示什么）。

## 第 4 步：设计规范
- 一套克制的设计系统：色板（含两套状态色的语义归一）、字体层级、间距、圆角阴影；组件清单（按钮分级、卡片、徽章、表格、弹窗、空状态、加载、Toast 反馈）。全部用纯 CSS 可实现的方式表达（CSS 变量）。

## 第 5 步：实施路线图
- 分成 3-4 个阶段，每阶段：改哪些文件、不破坏什么、大概规模、如何验证。要求每个阶段结束产品都完全可用（不搞大爆炸重写）。
- 第 1 阶段必须是"纯前端、不动 API、风险最低"的。

# 六、工作方式要求

- 全程用中文。
- 不要急于给终稿：先诊断和提问，我给答案后再出方案。
- 每个设计决策说明理由（为什么这么排、为什么这个颜色语义）。
- 这是内部效率工具，设计目标是"信息找得到、操作不走神、新手不迷路"，不是酷炫。克制优先。
- 涉及具体页面结构时，可以给 HTML/CSS 原型片段，但不要一次性重写整个 index.html。
````

## 追加追问（第二轮按需发给 Claude）

```text
- 详情页我倾向"左侧版本切换 + 右侧审阅工作台"的布局，你评估一下 vs 你推荐的方案。

- 给我第 1 阶段的具体改动清单：index.html 拆成哪几个文件、CSS 怎么组织、server.js 的 MIME 白名单要补什么。
- 出一份可以直接照着改的 CSS 变量表和按钮/徽章/卡片的 HTML+CSS 规范。
```
