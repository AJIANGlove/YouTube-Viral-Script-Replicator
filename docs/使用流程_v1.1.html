1. 流程总览：1.1 跟以前有什么不一样

老的流程是「选题 → 蓝图 → 脚本 → 审核 → 优化」四步直通。1.1 在前面加了一步**写前分析**，在后面加了一步**稿件检查**：

选题→ ⓪ 写前分析（1–4 分钟）→ 停在「待确认分析」，等你→ ① 蓝图→② 脚本→③ 审核→④ 优化→ ⑥ 稿件检查
一句话记住：分析阶段不写稿，只把「这题能不能写、写什么、用哪些事实、原片爆点由谁接」摆到你面前；确认之后才动笔。 稿件检查是写完之后的复检，只有一类问题会自动改。

2. 新建任务：三步填完

2.1 第 1 步：选框架资产

搜索框只匹配**框架名、源标题、频道名**，不匹配资产 id（比如输 kr11 是搜不到的，要输「一笔交易」或频道「수익구조 연구소」）。

2.2 第 2 步：主题与受众

三个容易踩的点：
  1. 「先做写前分析」默认是勾上的。勾了就会停下等你确认；不想用就手动取消。
  2. 「参考资料」空着会很难看：实测空着跑，事实表 20 条里 16 条标「待查」、2 条「假设」、1 条「估算」，只有 1 条是真事实。不是不能用，但稿子里的数字就没有依据了。
  3. 声音选「自动」的前提是选了频道。没选频道时「自动」等于不使用，会回落到资产的 Style。

3. 待确认分析：这是唯一需要你认真看的地方

点「开始生成」后，任务先进入 写前分析中，跑完停在 待确认分析，不会自己往下走。

上面这张是真跑的结果：结论是「调整后可写」，标题判为「部分一致」，所以标黄提醒你先看一眼。

事实表是写稿时**唯一允许使用的数字来源**。黄底越多，说明这题越依赖你补料。

3.1 你能改什么

位置怎么改改完的影响
标题展开「编辑分析 JSON」，改 title.final_title蓝图和稿子都用这个标题
事实表增 / 删 / 改条目（内容、来源、年份、地区、类型）写稿只能用表里的数字，删掉就不会用
模块取舍改每段的 decision决定哪段保留、哪段换内容、哪段删
留存地图改每行 status：承担 / 缺口-补料 / 缺口-接受弱化「接受弱化」的高峰不再计入留存检查的及格线
钩子改 hook.chosen 的序号（0/1/2）决定开场用哪一条
不能做的事：
  • 没有「逐条打勾」的界面——只能改 JSON 里的内容，不能勾选式采纳。
  • 必需字段不能删（verdict / title / thesis_card / facts / modules / retention_map / hook），删了确认会被拒绝。
  • JSON 语法错会直接提示，确认不了。

改完点「确认并开始写稿」。如果想补资料重来，用「补充资料后重新分析」，会重跑一次分析（再一次模型调用）。

4. 确认之后的四步

实测耗时（20 分钟那一单）：写前分析 205 秒、蓝图 102 秒、脚本 186 秒、审核 162 秒、优化 320 秒、稿件检查 111 秒，合计约 18 分钟纯模型时间。

按钮文案不准：界面上写的是「开始生成（约 3-8 分钟）」，但勾了写前分析 + 自动稿件检查后，实测 20 分 31 秒。这个文案应该改。

5. 留存检查：三个数字怎么读

指标含义这次实测
高峰承接原片的高峰有几个被新稿的章节声明接住12/12，全接住
第一个甜头开场第几秒给出第一个反常识数字；不能晚于原片30 秒（原片 29.76 秒，靠 0.5 秒容差通过）
高峰最大间隔新稿相邻高峰的最大间隔占全片比例，不能明显大于原片16% 对原片 16%
一个要知道的局限：这里数的是「蓝图里有没有声明 carries_peaks」，不是稿子里到底写没写。所以「12/12」只能说明结构上没丢，不能保证内容真好。真正的质量还得靠你读稿。

6. 稿件检查：谁能自动改、谁只给选项

编号查什么会自动改吗
K1标题和结尾结论对不上不改，给 3 个备选标题 + 1 个「保留标题改结尾」
K2核心证据超过 3 年不改，给补料 / 写明「当时」/ 改论点
K3数字、年份自相矛盾会改，但要求原句在稿里恰好出现一次；改前版本存档
K4为凑节拍放进来的段落不改，标出来并说明删了会丢哪个高峰
K5篇幅、数字密度不改，只提示
当前的最大缺口：报告里给了选项，但界面上没有「一键采用」。 K1/K2/K4 的「1. 2. 3.」是纯文本，点了没反应；想落地只能把稿子复制出去手改，或者补资料重跑。K3 虽然自动改了，也没有「撤销」按钮，只有改前版本存在数据里。

7. 设置页与频道声音

声音设定的用法：设置页填频道名 + 语言 + 一句说明，粘贴 1–3 篇你自己的旁白 → 「AI 起草」→ 核对后保存。之后新建任务时，选了对应频道、声音选「自动」，就会注入到写前分析、写稿、优化三步。

现状限制：只有「AI 起草」这一条入口，没有从空白手动新建的表单（可以通过编辑 JSON 区改）。另外「语体」和「称呼观众」是必填，缺一个保存不了。

8. 资产库与留存卡

每份资产的结构段都有一张留存卡，写前分析的「留存地图」和「替换库」都来自它。179 份里 167 份的「抽象动作 / 替换条件」经过 AI 重写，剩下 12 份仍是程序生成版（7 项齐全，只是抽象动作等于段目的）。

9. 常见状态与故障处理

状态 / 现象含义怎么办
写前分析中模型在查事实、写论点等 1–4 分钟。重启服务会自动重跑，不会卡死
待确认分析等你核对列表里点「去确认」，或直接进详情页
失败 + 429渠道限流/额度等 1 分钟点「重试」
失败 + 输出被 max_tokens 截断单次输出超上限设置里把 Max Tokens 调大（现在 65536 已经很大）
分析结论是「换框架」这题不适合这个资产别往下写，换一个资产重新分析
稿件检查「待选择」很多大多是证据时效问题回分析里补事实，或重写；不要忽略

11. 已知待改的地方

  1. 「开始生成（约 3-8 分钟）」文案不准——勾了写前分析和自动检查后实测 20 分钟。建议按勾选状态动态显示。
  2. 参考资料框不够醒目——空着跑会产生 16/20 条「待查」，应该在框上直接写「不填会导致大量待查」。
  3. 稿件检查没有「一键采用」——选项是纯文本，无法点击落地；建议做成按钮，把 after 文本写回稿子。
  4. 分析和检查都没有「逐条打勾」——分析只能改 JSON，对非技术用户偏难。
  5. 声音设定没有手动新建入口——只能 AI 起草。
  6. 留存检查是「声明式」的——只核蓝图有没有声明接住，不核稿子有没有真写。
